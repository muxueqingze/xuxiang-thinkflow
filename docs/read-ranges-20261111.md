# 范围读取与连续精确编辑 · 2026-11-11

将[成熟harness方向](harness-direction-20261110.md)的第二项落到同一条执行链：按任务读取相关代码，随后直接精确修改，不为取得修改基线再读一遍全文。默认工程指引不变，能力与简短语法说明由框架协议提供。

## 实现

`read(path, offset, limit)`的offset是从1开始的行号，limit是行数；两者均可省略。文本与原生接口共用实现，多个独立读取继续在同次生成中合批反馈。正文保持原样，返回范围、总行数和下一行作为后缀，避免污染可复制的old_text。单行超过显示预算时明确提示行内截断，避免循环同一offset。

显式范围读取按64KiB块计算整文件SHA256和行数，只保存所选片段。Unicode字符范围与UTF-8字节预算分开计算，CRLF原样保留。无范围读取保持原有预算内前缀快路径；大文件尾部可读取，既有8MiB文件修改上限不变。范围读取需要扫描本地全文以确认版本，换取模型只接收相关片段。

`ReadObservation`只存版本和已读字符区间。同版本相邻范围合并；exact edit要求旧文本在整个文件中唯一（包括重叠匹配），并且完全处于已观察范围。成功修改后，替换正文及其他已读片段按长度差更新位置，可以连续执行后续已知修改。外部修改更换版本后，旧片段不能用于新版本。未确认的修改、脱敏文本和会话reset不会产生新的完整基线。

完整读取、冻结附件及自身完整写入保持原连续操作。局部编辑不会把片段升级为全文覆盖许可；write、append、touch及copy覆盖已有目标继续使用完整基线。原来的文件变更记录和原子替换机制不另造一套。

旧read回执曾带未使用的通用offset=0/limit=8000；加载时只迁移这个已知旧默认对。默认read指纹保持原值，显式范围进入指纹。recall继续使用从0开始的字符偏移和默认8000字符，不混用两种单位。
