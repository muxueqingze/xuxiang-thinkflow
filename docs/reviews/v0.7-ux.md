## 问题清单

### [P1，已修复并独立复核] 大窗口的长授权、队列和多行输入同时出现时，停止与发送落出屏幕

- 原位置：`desktop/renderer/styles.css` 的 `.composer textarea`、`.queue-panel`、`.approval-panel` 固定高度组合；修复位置：当前文件约 251–256 行的统一高度预算。
- 独立复现：真实 Electron 中打开授权参数约 160 次重复文本的 bash 请求，保留 6 条待发任务，输入 16 行草稿，同时展开账本。所有模型数据来自 localhost SSE，未批准或执行该 bash 请求。
- 初次实测：窗口外尺寸 1380×900、实际内容区 1366×864 时，composer 底部为 921.75；发送与停止底部为 905.08，均超过内容区。此时较小的 1000×700 窗口由于专门的媒体规则反而没有同样失败。
- 影响：用户在任务等待授权时无法直接点击停止或加入队列；不是单纯留白或字体偏好问题。
- 修复方向：按可用高度分配授权、队列、输入区域，而不是只给小窗口增加特例。
- 独立复核：实现者完成后，审查者重新启动隔离 Electron，重新创建同一极端状态，重新采集几何并实际查看两张截图。关键按钮均在视口内，消息区仍有可阅读空间。

## 独立实测

均启动真实 Electron，由 Playwright 操作真实 renderer、preload、main 和 Python service。每次使用独立 `THINKFLOW_TEST_USER_DATA`、临时工作区与 localhost SSE；没有访问真实工作区、真实模型或付费端点。

| 检查 | 实际验证方式与结果 |
| --- | --- |
| Enter / Shift+Enter / IME | Enter 发起请求；Shift+Enter 保留换行；合成输入状态的 Enter 没有产生请求。IME 使用 DOM composition/keyboard 事件，不宣称覆盖所有 Windows 输入法驱动。 |
| 成功后续发 | 本地保持流结束后，队列中的第二条才成为第二次真实 backend/model 请求；发送过程未发生并行执行。 |
| 拒绝/停止后队列暂停 | 拒绝长授权后待发项保留。更严格的“已接受但丢回执”场景中，停止后继续队列没有触发重发。 |
| 有草稿时取回 | 16 行现有草稿不被取回动作覆盖，队列数量不变；清空输入框后可取回第一项，队列减一并暂停。 |
| 草稿持久化异常 | 在真实页面中仅对草稿键注入 `QuotaExceededError`，输入新内容后 Ctrl+N，再切回旧会话；新内容仍由内存后备保留，保存失败提示仍在。未声称关闭进程后能恢复未成功持久化的草稿。 |
| 快速切换 | 同一事件回合连续点击两个会话，等待忙碌状态结束后，选中 DOM 的 session ID 与真实 backend state 一致。 |
| 工作区与会话隔离 | 新会话/新工作区输入为空；返回原工作区恢复对应会话及其草稿。 |
| 搜索/置顶/归档/恢复 | 实际重命名为“独立检索目标”，搜索后只剩该会话；置顶后排首位；归档后默认列表隐藏，显示归档后重新出现；恢复后标题和会话保留。 |
| 重启 | 重启恢复选中工作区/会话、草稿与暂停队列，没有自动发送待发项。 |
| 长授权 + 6 条队列 + 16 行输入 + 账本 | 此为原 `electron-ux.cjs` 未覆盖的恶劣组合；发现上述 P1，修复后独立重复该失败项通过。 |

证据：[交互检查](../evidence/v0.7-review/independent-interactions.json)、[草稿配额故障](../evidence/v0.7-review/draft-quota.json)、[会话元数据检查](../evidence/v0.7-review/session-metadata.json)。

### 已接受请求的启动回执丢失

故障注入位置在 Electron IPC 主进程测试包装器：先等待原 handler 调用真实 backend 完成，再仅把一次 `run` 成功回执替换为错误。该请求已经进入真实会话记录并请求 localhost SSE，故不是“调用前直接报错”的假覆盖。

实测顺序：第一条任务运行 → 第二条加入队列 → 第一条结束 → 第二条实际被接受但回执丢失 → 看到“发送状态待核对” → 停止 → 尝试继续 → 关闭并重启 → 再尝试继续。

结果：整个过程模型请求数始终为 **2**；会话保留第二条用户消息；待核对项跨停止和重启保留，未被自动消费。主会话随后将待核对时的“继续队列”按钮直接置为禁用；独立验证已覆盖更底层的 drain 阻断行为。

证据：[故障序列及计数](../evidence/v0.7-review/lost-ack.json)、[重启后待核对截图](../evidence/v0.7-review/restart-uncertain.png)。
