## 发现的问题与定向复核

### R1 · P1 · UI 回退留下未知结果，但服务允许继续运行——已关闭

位置：`src/desktop_service.py` 的 `revert_workspace_change` 分支（现第 839 行起）。

独立复现使用 FakeAgent + 真实 Executor/ChangeStore：读取 `old`，工具写成 `new`；对 ChangeStore.complete 注入 OSError，然后从服务 RPC 回退。文件实际回到 `old`、变更账本留下 `revert/unknown`，服务却仍为 idle、recovery_required=false；继续 submit 的 `next` 真实进入 FakeAgent。根因是工具调用会进入 service intent journal，UI 回退原先没有经过同样的恢复边界。

实现者修复后，UI 回退先写入 `channel=ui` 的持久意图，成功保存后再记完成；异常保留恢复要求并暂停队列。独立按原注入点复核：当前进程和重新打开服务均拒绝后续任务，明确核对并继续队列后才运行一次。通过。正式回归：`tests/test_v08_cross_review.py::ServiceCrossReview.test_ui_revert_final_receipt_failure_blocks_run_across_restart`。

### R2 · P1 · 变更预览与回退字段未对齐——已关闭

### R3 · P1 · 明确未接收的候选原先没有正常 UI 恢复出口——已关闭

修前源码路径：提交前保存本地候选并清空 composer → 附件版本过期被后端拒绝 → 精确查询回执返回 null → 只能原样重试候选或只读查看；pending 会禁用新发送。旧附件 hash 无法通过原样重试，刷新仍加载该候选。该问题从明确可达的源码控制流发现，修前未单独运行该版本。

实现者增加“返回草稿”，只在精确查询无受理记录后由用户主动触发。独立 Electron 实测：选择附件后外部修改文件，提交被拒绝，模型请求为 0；先输入新文本草稿再点返回，新草稿原样保留；清空文本后主动返回，旧任务及其附件恢复，待确认标记清除。通过，不把已接收但丢 ACK 的任务当未接收重发。

### R5 · P2 · 同水位旧会话快照可覆盖新会话——已关闭

## 收口后的追加定向复核：原生文件工具兜底

主会话根据另行完成的真实模型观测，调整了默认原生工具 schema：可预测的 write/append/edit/mkdir/touch/copy 默认由流式标签承担；当本次 run 发生解析错误后，才开放原生写入兜底。本审查者只针对该补丁新增 `tests/test_native_write_fallback.py`，没有重新展开审查。5 项分次通过：

- OpenAI、Anthropic 默认 schema 排除 6 个可预测文件工具，read/bash 保持；显式 allowlist 优先，deny 仍能排除，disable 全部原生工具仍生效；兜底也尊重 deny。
- 一段输出内 write → append 的真实磁盘操作仍只有 1 次模拟 API 请求，2 条 ledger 均为 delayed，未开启兜底。
- 残缺标签触发解析错误后，下一请求出现写入 schema 与 PROTOCOL FALLBACK 状态；status_notice 明确告知。原生修复的事件/ledger flow 为 blocking，快照保留标志，下一次新 run 重置为默认 schema。
- 显式 allowlist 只有 read 时，解析错误不会扩大列表。
- 兜底原生写入发生最终变更回执落盘失败时，实际文件虽已写入，账本仍为 unknown，runtime 在第 2 次请求后停止，没有第 3 次模型调用。

所有新增复核使用 httpx.MockTransport，没有网络请求。初版测试把流式标签 id 写成了英文、并误猜状态标记文字；修正为既有协议要求的十进制 id 和实际标记后，仅重跑受影响项，不将测试 fixture 错误记为产品缺陷。

## 真实模型暴露后的 P1 定向修复：文件正文中的 Markdown 围栏被删除

主会话真实模型测试发现 `tf-write` 生成的 Markdown 示例内容为空，示例代码反而显示在对话中。本审查者独立构造最小文本 SSE：`<tf-write id="1" path="doc.md"># Demo\n```python\nprint(1)\n```\n</tf-write>`，经真实 AgentLoop 与隔离 Executor 执行，修前磁盘结果确实仅为 `b'# Demo\n'`。没有读取真实配置或密钥，也没有发起真实模型请求。

根因有两层，均在 `src/text_filter.py`：MarkdownFenceCommandGate 不知道自己正处于活动文件命令中，直接删掉围栏行及其中代码；SafeTextStreamFilter._feed_line 又优先识别 Markdown，绕过尚未闭合的命令缓存，把文件正文中的围栏/代码当作可见回复。修复为：gate 只在顶层排除代码示例，轻量跟踪活动命令开始/结束，命令正文内所有字符原样交给 parser；可见文本过滤器遇到未完成命令时先继续处理命令缓存，不让内部围栏绕行。解析、校验和执行仍由原 parser/Executor 负责。legacy 跟踪仅在显式配置开启时生效；AgentLoop 构造参数接线由主会话修改。

新增 `tests/test_markdown_payload.py` 共 8 项，分次通过：单个 SSE chunk、逐字符拆分、append/edit 内的反引号及波浪号围栏、文件命令前后顶层 fenced examples 不执行、不完整命令正文不泄露、正文内未闭合 Markdown 围栏不吞掉后续合法命令，legacy 开关一致性，以及未完成开标签不会绕过随后顶层代码示例的保护。真实文件字节与预期完全一致，text_delta 和 assistant 正文均不出现 `print(1)`。另仅复跑原有 4 项文本过滤相关测试，全部通过。未重审其他已通过模块。

这是主会话明确授权的故障修复，本审查者此次成为 text_filter 的实现者，以上属于独立复现后的修复自测，不冒充另一名审查者对该补丁的独立验收；最终真实模型/交付包复核仍由主会话完成。
