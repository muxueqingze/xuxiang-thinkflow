# 工作区搜索验证 · 2026-11-13

`grep`、`glob` 与 `list_files` 共用惰性遍历。目录搜索采用工作区内的 `.gitignore`，支持嵌套规则、否定模式和非 Git 工作区。明确指定被忽略的文件或目录时可直接搜索，目录内部的规则照常生效。遍历在工作线程执行，取消信号在条目与行之间检查。grep 保留 Python 正则、UTF-8 解码、现有权限及密钥脱敏，返回工作区相对路径、行号和命中行。结果超过上限才标记截断，显式路径和实际 I/O 错误回传给调用方。规则由 [PathSpec GitIgnoreSpec](https://python-path-specification.readthedocs.io/en/stable/readme.html) 解析。

在 Windows 11、Python 3.12.10 上，将基线 `38a0807` 与新执行器按交替顺序搜索同一语料。普通语料含 2,000 个小型 Python 文件和一个末尾标记文件，表中取热身后的 7 次中位数。随后加入 `.gitignore` 排除的 3,000 个依赖文件，对有效结果相同的查询取 4 次中位数。

| 查询 | 基线 | 新实现 |
|---|---:|---:|
| 普通语料，常见标记，返回前 20 条 | 31.4 ms | 10.0 ms |
| 普通语料，唯一标记在末尾 | 495.1 ms | 498.8 ms |
| 普通语料，无匹配 | 508.6 ms | 503.7 ms |
| 有 3,000 个被忽略文件，唯一源码标记在末尾 | 1,277.5 ms | 507.9 ms |

当同一标记同时出现在依赖和源码中，基线的 20 条预算全部由依赖占用，新实现返回唯一的源码命中。

- 正式回归覆盖嵌套及否定规则、Unicode 路径、显式文件与目录、Python 正则反向引用及后顾、权限、错误、截断及工作线程退出。PathSpec 0.12.1 和 1.1.1 均通过。既有文件权限、读写版本、按行读取和进程契约检查通过。
- 按桌面构建参数冻结 `scripts/desktop_entry.py`。PyInstaller 自动收集 PathSpec，实测冻结后的 Windows 服务通过本机回环 HTTP 的固定工具调用获得 `源码.txt:1: SEARCH_MARKER visible`，被忽略的依赖没有命中。测试服务正常关闭，未调用外部模型。桌面构建随包写入所装 PathSpec 的版本、源码地址与上游许可原文。 [MPL 2.0 第 3 节](https://www.mozilla.org/en-US/MPL/2.0/)
