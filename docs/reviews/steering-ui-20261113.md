# 桌面运行中补充输入 · 2026-11-13

运行期间，输入框底栏在发送按钮旁显示「补充当前 / 排队任务」，每次发送后回到「补充当前」。Enter 发送所选方式，Alt + Enter 直接排队，Shift + Enter 保持换行；输入法组合期间两种发送按键均不提交。空闲时按原方式发送新任务。待发列表复用现有队列，在条目开头标明两种投递方式；暂停、编辑、移除及回执核对继续走原链路。

## 实测

- `npm --prefix desktop test`：15 通过。桌面改动与测试脚本语法检查、`git diff --check -- desktop` 通过。
- `node desktop/tests/electron-steering.cjs`：真实 Electron 与 Python 后端、隔离 user-data、隐藏窗口、回环 SSE 模型。首轮流保持未结束时，先排队一条，再补充当前任务，再用 Alt + Enter 排队；模型调用保持 1 次。放行首轮并读取文件后，第二次请求同时带有读取结果及恰好一份补充。第三、四次请求分别执行先后两条排队任务，总计 4 次。丢失已接收补充的提交回执后，精确查询 1 次、补充提交 1 次。通过输入法组合、Shift 换行、独立草稿保留及队列清空断言。窗口尺寸 1000×700、右侧工作台展开时，发送底栏控件的实际边界全部位于输入框内，左右不重叠；截图实查文字与图标清晰。
- `electron-workbench.cjs`：以隐藏窗口、独立 profile 运行，通过 6 项；含提交回执丢失核对、排队编辑、停止暂停、重启后继续队列，及 1000×700 工作台布局。队列场景改用 Alt + Enter。
- `electron-ux.cjs`：隐藏窗口与隔离 profile 下通过 11 项，合计 11 次模型请求，未出现页面异常。覆盖排队顺序、停止和失败后暂停、重启恢复、消息阅读位置和回执核对。测试夹具从最后一条用户消息读取单行任务，侧栏开合通过 ARIA 状态判断，阅读位置通过滚轮输入验证。1000×700 窗口下，输入框右边缘为 602 px，工作台左边缘为 618 px，设置保存按钮底边为 656 px，视口高 664 px。

测试脚本保留在 `desktop/tests/electron-steering.cjs`。本轮临时 profile、工作区、测试启动包装和截图已回收到回收站，测试 Electron 和回环服务均已退出。
