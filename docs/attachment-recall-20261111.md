# 压缩后回取冻结附件

`recall` 接受 `request:N:input`，返回该次提交冻结的执行输入，包含用户原话和当时附加的文件路径、revision 与正文。`request:N` 仍只回取用户原话。桌面附件的正文保存在提交时生成的 JSON 中，`offset`、`limit` 和字面 `query` 都作用于这份执行输入。

旧请求有冻结输入时，压缩条目会列出对应引用。条目因摘要预算省略时，摘要仍给出引用格式。会话恢复和分支复用已保存的执行输入，旧快照也可直接用新引用回取，下次压缩会更新摘要提示。压缩和保存无需额外模型调用或新存储。编辑工作区文件时继续读取当前版本。

会话上下文定向回归通过 9 项。附件用例走真实桌面队列和会话持久化，模型响应由本地 MockTransport 提供。提交附件后修改磁盘源文件，发送 `Continue.`，连续压缩两次，再恢复并分支。分支的模型请求先看到引用，调用 `tf-recall` 后才收到冻结附件中部约束。恢复时还核对原始路径、revision、精确字符范围和独立保存的用户原话。
