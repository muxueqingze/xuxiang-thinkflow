# 跨阶段维护、恢复与 token 用量

本轮用 OpenCode Go 的 DeepSeek V4.1 Flash（thinking 开启、high）做两类项目维护。每题开始前冻结题面和外部验收程序。每个阶段由新进程重新打开同一个会话和项目，直接检查磁盘上的代码、API 行为、CLI 输出字节和退出码。HTTP 正常结束、模型给出答复、实物通过是三个独立结果。总 token 为供应商报告的输入与输出之和，包含缓存命中的输入。

## 同场结果

ThinkFlow 实测源码为 `be766c0`，对照为 Pi 1.0.1。两边在每个阶段都正常结束并通过本题全部独立检查，所列请求都取得了完整上游用量。表内括号为 API 请求次数。

| 工作负载 | 双方逐阶段验收 | ThinkFlow 总 token | Pi 总 token | 总 token 降幅 |
|---|---|---:|---:|---:|
| 运费库维护 | 4/4、8/8、12/12 | 125,995（13） | 248,509（19） | 49.3% |
| 插件解析器兼容改造 | 5/5、8/8、12/12 | 73,171（10） | 244,913（23） | 70.1% |
| 两题合计 | 六次阶段验收 | 199,166（23） | 493,422（42） | 59.6% |

运费三个阶段 ThinkFlow 分别用 15,866、36,900、73,229 token，Pi 分别用 12,880、89,965、145,664。阶段 B 的 Python 实际从 `request:2` 取得了 13,362 字符。两边默认自动压缩均未触发。旧版 `d99216d` 在同一轮完整对照用 151,929 token、15 次请求，实物同样全过。新版比它少 17.1%。[交付版](../evidence/freight-final-20261119.json) · [Pi](../evidence/freight-comparison-pi-20261119.json) · [旧版](../evidence/freight-comparison-prior-20261119.json) · [修复裸标签前的候选](../evidence/freight-comparison-delivery-20261119.json)

插件题三阶段，ThinkFlow 分别用 10,195、34,848、28,128 token，Pi 分别用 44,276、92,564、108,073。第三阶段前，两边均完成一次压缩。ThinkFlow 在本地完成，Pi 的两次模型摘要请求均已计入。压缩后，两边都实现了第一阶段冻结的退出码、错误文本与 UTF-8 逐字节约定。[ThinkFlow](../evidence/plugin-resolution-thinkflow-repair-20261119.json) · [Pi](../evidence/plugin-resolution-pi-20261119.json)

两题在总 token 外还呈现了不同的成本结构。运费题 ThinkFlow 的输出为 19,449 token，Pi 为 14,731，服务端报告的标价分别为美元 0.01463062、0.01310352。插件题的实扣 Go 额度分别为美元 0.00998807、0.01468143。正式样本每个工具在每道题上各一次；这些数字适用于这两条具体工作流。

## 工程改动

- Python 工具可以把本会话的用户原文作为标准输入。对于长清单，脚本可直接筛选、聚合或核对原文，无需模型重抄每条记录。冻结附件和历史请求在重开后仍可精确引用。
- 同工作区的会话快照保存已确认的文件 SHA-256 和实际已读范围。修改时仍核对当前版本。只读过局部时不能覆盖全文，待反馈的读取不会变成已读，外部改动会产生冲突。
- 大冻结附件在当前任务中完整可见。该任务给出正文交付、随后开始新任务后，请求可用文件名和冻结输入引用替代历史附件正文。用户的实际指令以及附件之后追加的工具观察继续保留。通过配置可将历史附件保持全文。没有附件路径元数据的旧快照沿用全文方式。

桌面受控试验初次发送相同的 40,827 字节附件，随后发出六个内容相同的后续请求。请求输入合计从 292,356 字节降至 24,858 字节（−91.5%）。两组都在两次手动压缩、冷重开和原文件被外部修改后，用真实 Python 验证冻结输入的 SHA-256 和中部规则。这里计量的是请求输入字节，模型响应使用测试流。[逐请求数据](../evidence/attachment-projection-20261119.json)

## 验收口径

运费库经历计价 API、160 条调度公告、取消与恢复及 CSV 交付三个版本，检查数依次为 4、8、12。前一阶段必须记住后续 CSV 的字段顺序、批次字面量和换行约定。使用默认自动压缩策略，计量实际发生次数。

插件兼容解析器是独立留出题，输入以工程需求为主。阶段 C 需要用早先约定的退出码、中文错误字节、标准输出和标准错误交付 CLI。第三阶段前显式压缩；压缩调用也纳入成本。

如需复跑，先在本机环境设置 `OPENCODE_GO_API_KEY`。例如 `python bench/long_context_20261110/freight_live.py --run thinkflow --ref be766c0 --output new-freight.json`。插件题使用同目录的 `plugin_resolution_live.py`。对照 Pi 使用 `--run pi`。运行器使用合成工作目录和本地计量代理，拒绝复写已有证据。

## 调试中保留的反例

早期运费题使用每请求 4,096 输出 token 上限。第一版在所有请求中都展示 Python 引用示例，三个阶段只过 4/4、3/8、3/12，虽然仅用 44,016 token。后续将提示限于真实大输入并指明当前引用。早期工作目录别名也影响了绝对路径可执行性，最终对照统一为真实的合成目录。[失败候选](../evidence/freight-long-request-stdin-20261118.json)

同一早期设置的 Pi 重复样本为 201,460 token，实物全部通过；另一条 Pi 和一条旧版 ThinkFlow 的用量记录不完整。一次宿主重启同时中断两个第三阶段，已有文件的后验检查与完整运行分列。最终比较统一每请求 16,384 输出 token。[早期 Pi 完整重复](../evidence/freight-long-pi-clean-20261119.json) · [Pi 缺失用量](../evidence/freight-long-pi-20261118.json) · [旧版缺失用量](../evidence/freight-long-thinkflow-20261118.json) · [原始工具顺序](../evidence/freight-long-tool-trace-20261118.json) · [中断记录](../evidence/freight-interrupted-20261119.json)

插件题第一版仅用 74,937 token，但阶段 B 只过 5/8。恢复后模型使用已占用的工具 ID，写入未执行。下一次回复只含三个缺少 tf- 前缀的 read 标签，被当成了交付文字。阶段 C 后来补上代码也没有改变阶段 B 的判定。现已在跨阶段运行状态与失败回执中给出下一个可用编号，失败恢复中的裸标签沿用一次有上限的继续机制，工具不会凭裸标签执行。用确定性重放核对副作用，再按原题从 A 开始复跑。[失败阶段的回执](../evidence/plugin-resolution-id-conflict-20261119.json) · [该次全程实测](../evidence/plugin-resolution-thinkflow-20261119.json)
