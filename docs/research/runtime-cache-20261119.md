# 长计划的缓存前缀与重复输入

基线为 `4aa0506`。此前每次工具 ID 递增，运行时都会把当前计划、执行环境和下一条 ID 一起追加到历史。每份副本都会随以后的请求再次发送，也会占用本地压缩预算。

现在按字段记录已发送的状态。计划、工作目录或工具配置发生变化才追加新值，计划清空会明确通知模型。组装请求时只在压缩后仍保留的消息中查找已有值，缺失的当前信息会随下一次请求补齐。旧会话已发送的文本按原样回放。供应商缓存选项沿用现有配置。

## 固定工具轨迹

通过 HTTP MockTransport 实走一次计划更新、30 个不同文件的读取和最终答复。计划含 8,245 个 JSON 字符，使用默认压缩预算。下表的字符数是逐包序列化 messages 的累计值。

| 指标 | OpenAI 兼容，修复前 → 后 | Anthropic Messages，修复前 → 后 |
|---|---:|---:|
| HTTP 请求 / 成功工具回执 | 31 / 31 → 31 / 31 | 31 / 31 → 31 / 31 |
| 累计消息 JSON 字符 | 3,691,550 → 457,294 | 3,802,018 → 695,192 |
| 保留上一次完整消息前缀的相邻请求 | 29/30 → 30/30 | 29/30 → 30/30 |
| 自动压缩次数（含任务收尾） | 1 → 0 | 2 → 0 |

在第 10 包，两种协议的计划都从 9 份降至 1 份，环境从 10 份降至 1 份，10 个工具戳记全部保留。强制压缩后完整计划可重新送达；保存再载入会话得到相同请求正文。回归入口为 `tests/test_prompt_cache_options.py`。

## OpenCode Go 实网用量

模型为 `deepseek-v4.1-flash`，关闭思考，使用 OpenAI 兼容接口及流式 usage。缓存读取数来自每个请求的服务端回报。服务端未单列缓存写入量。

| 场景 | HTTP 请求，前 → 后 | 输入 token，前 → 后 | 缓存读取，前 → 后 | 未命中输入，前 → 后 | 输出 token，前 → 后 |
|---|---:|---:|---:|---:|---:|
| 固定六阶段请求回放 | 6 → 6 | 18,263 → 10,544 | 13,184 → 8,064 | 5,079 → 2,480 | 166 → 172 |
| 模型自由执行，两轮各四个文件 | 14 → 15 | 52,538 → 28,718 | 39,808 → 24,064 | 12,730 → 4,654 | 440 → 498 |

固定轨迹由 harness 执行脚本化的写文件操作生成。使用独立会话和实验标记，交替向同一网关回放两组请求；每个响应都返回了该阶段计划中的正确值。首包两组缓存读取均为零，后五包两组均命中。累计输入减少 42.3%，加权命中率从 72.2% 到 76.5%。

自由执行要求模型从保留的计划里找出各阶段的随机值，逐文件写入并确认。两版各交付 8 个文件，逐字节全部正确。第一轮请求数为 7 → 8，反转起跑顺序后第二轮为 7 → 7。第二轮的双请求任务均在首轮执行一次工具，第二轮无工具。这次修改降低了每轮输入；模型是否同轮给出收尾答复仍影响请求总数。
