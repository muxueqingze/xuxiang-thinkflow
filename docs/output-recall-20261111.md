# 完整工具输出与会话回取

2026-11-11。落实[成熟harness方向](harness-direction-20261110.md)的第一个单元：让工具输出在截断、压缩、取消及会话切换后仍可回取，不增加摘要模型调用。

## 行为

- Shell/Python持续排空stdout和stderr，将完整的模型可见UTF-8文本流式落盘，内存保留有界尾部。默认预览仍为每路8万字符；短输出原样返回。已配置provider凭据在跨chunk边界也先脱敏再归档。
- 执行回执给出短引用，如`receipt:3:stdout`、`receipt:3:stderr`。沿用`recall(ref, offset, limit)`，按字符精确回取；加可选`query`可直接定位字面关键词的首个匹配行，返回匹配位置和有界原文，避免猜偏移。多个独立回取同批反馈。正常短结果不附加长引用说明，也不单独开启recall提示。
- 原始结果完整性与账本预览裁剪分开。旧账本仍按预算压缩；已经保存的完整输出不被改写，原始read完整性继续用于已有精确去重。被裁剪的命令正文也留下原文引用。
- 取消和超时先结算已经收到的输出，再记录状态；取消仍停止任务、保留现有未确认副作用提示，不自动续跑。
- CLI新会话清除原始要求、输出索引、计划及命令去重状态，避免旧上下文或旧ID进入新会话。

## 存储生命周期

每个实际SessionStore快照旁有同名`.outputs`目录：`session.json`对应`session.outputs`，桌面`<id>.json`对应`<id>.outputs`。文件按内容地址去重，回执短引用到文件的映射保存在快照中；复制/保存同一根时不逐文件重复检查磁盘。

JSON中的输出根为相对路径，载入时按该JSON位置解析。history只引用原根，不为每次快照复制原文；fork复制自己引用的文件到独立根，父会话目录不再可用时，分支仍能回取。归档会话与history淘汰不删除仍可能被引用的原文。

SDK未绑定存储时使用实例专属临时根，close后清理；SessionStore.save会先把临时原文复制到正式根再保存JSON。CLI `--no-autosave`沿用临时根，显式保存仍可持久化；正常退出清理本轮临时输出。正式原文是会话状态的一部分，与快照目录一起保留；当前没有新增会话删除入口或按条数清除原文的策略。

Markdown导出增加“短回执引用→字符数→本地文件路径”索引，继续作为本地记录查看，不将全文塞进导出，也不作为离机恢复包。
