# 续想：harness 能力地图

2026-09-29。这里区分已经实现、需要补强和未来方向；没有把规划标成完成。

## 续想应该继续坚持什么

「少一次模型回合」只有在没有跳过必要观察时才有价值。继续围绕输出侧的可预测操作建立执行流水线：生成时排队，信息依赖处设边界，用执行回执证实结果。不要把所有 shell、搜索甚至其他 agent 都塞进无反馈队列。

桌面端的价值是让用户看见生成、执行与等待的差别，同时能中止、授权、恢复和核对产物。核心运行时保持可以脱离界面使用。

## 能力与优先级

| harness 能力 | 本版状态 | 下一步有价值的扩展 |
|---|---|---|
| 工具分流与顺序 | tf-* FIFO、信息型 barrier、native schema 注册 | 有明确读写集合后才考虑无冲突操作并行 |
| 失败与停止 | 失败抢占、取消清理、回合/时间/连续失败上限 | 队列背压、按工具资源配额、标准化错误分类 |
| 长程状态 | 原子快照、摘录、恢复/分支、任务计划与执行证据 | 显式接力摘要、验收条件语义校验 |
| 副作用可审计 | SHA256读写基线、命令回执、持久变更diff与文本回退、未知状态恢复 | 外部协同编辑、Git事务与更广产物类型 |
| 人类控制 | 桌面逐次授权、只读/平衡/开放策略 | 操作级capability授权与外部OS容器沙箱 |
| 凭据 | 桌面系统加密、快照/事件不回读密钥 | 多provider凭据与独立credential broker |
| 上下文 | 工作区指引、skills按需读取、历史摘录 | 检索预算、文件内容搜索、较早消息分页 |
| 模型适配 | OpenAI/Anthropic兼容流、DeepSeek思考/native后续轮、诊断和模型列表 | 更多端点契约、明确的能力协商 |
| 用户工作台 | Windows desktop、会话整理、后端队列/回执查询、文件预览/引用/diff/回退、计划、连接诊断 | 跨会话隔离并行、消息分页、无障碍/多平台发布 |

| 多agent | 未实现调度器 | 隔离工作区、任务依赖图、合并仲裁、预算、交付验收再启动worker |

## 建议的下一阶段

v0.8已经实现上一轮前三项基础：权威输入接收、变更层、任务与证据层。[最新同模型基准](../bench/harness_benchmark_20260929/reports/summary.md)中续想仅7/12正常交付，虽然10/12产物通过；成功配对的token和用时也没有整体优势。因此先修tf/native误路由、无效计划回执纠错、长思考触顶后的无进展续跑、Windows shell契约及遗漏交付物，保持已验证产物不被无效收尾拖住。单轮预算敏感性尚未测，不能把这组结果外推为所有配置。

之后再推进这些能力：

1. **长任务体验**：较早消息分页、文件内容检索、可复用任务模板与显式接力；输入回执和文件快照的可控保留策略。
2. **工具生态**：MCP stdio先接一个真实工具，验证授权、取消、超时、大输出和故障恢复后再扩目录。
3. **协作与隔离**：跨会话并发需要独立工作区/进程、依赖关系和合并仲裁；共享目录同时写不是可靠调度。
4. **生产分发与观察**：签名安装包、更新/回滚机制、更多平台和长时运行实测。当前交付是未签名Windows便携包。
5. **对照评估**：已完成同请求参数的三harness小套题；还需不同输出预算和纯机制消融。不能把目前36次样本或流式重叠事实解释成统计显著的速度/费用优势。

2026-09-29 对官方ZCode固定版本的定向参照见 [架构勘察与主会话复核](research/zcode-scout.md)。借鉴输入接收、权威状态与写前条件的机制，保持续想的Python运行时和流式工具FIFO；现阶段不迁入其整套多端Host、远程路由或monorepo。

上面的下一阶段仍是规划；已实现范围按表格及v0.8证据判断。两篇官方材料也支持把长期状态、渐进交付和执行边界放在框架层：[长程agent harness](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)、[Electron安全边界](https://www.electronjs.org/docs/latest/tutorial/security)。

## 应如何证明核心思想有价值

用相同任务分别运行「逐条同步工具」「原生批量工具」「续想流式工具」，保留统一验收与同一环境。比较完成率、错误写入率、总时长、实际输入输出用量、重试次数和人工介入；缓存命中与非缓存输入分列。不要只展示成功样本，也不要把历史供应商返回字段缺失解释成零成本。

优先测试四类任务：批量独立文件生成、读改写混合任务、运行测试后的修复、长输出截断/网络中断。续想最有可能在第一类获益；信息密集任务能否获益需要实测。
